# Support Hub — Small Business WordPress Site (Demo Project)

A demo WordPress project built to show practical, working knowledge of WordPress for a customer-facing/support role: managing content, customizing a theme safely, using plugins, and troubleshooting common issues.

> **Why this exists:** built as a personal project ahead of an interview that requires basic WordPress knowledge. It's intentionally scoped to what a support/ops person actually touches day-to-day — not a from-scratch theme framework.

## What's in this repo

| Path | What it shows |
|---|---|
| `wp-content/themes/support-hub-child/` | A **child theme** of Twenty Twenty-Four — the safe, correct way to customize WordPress without losing changes on updates |
| `wp-content/plugins/simple-faq-accordion/` | A small custom plugin (shortcode-based FAQ accordion) — shows I can go beyond just using plugins when one doesn't exist |
| `docs/CONTENT-PLAN.md` | Sample site structure & content for a small business (pages, FAQ, contact) |
| `docs/TROUBLESHOOTING.md` | Common WordPress issues a support person gets asked about, and how I'd resolve each |
| `docker-compose.yml` | Spin up a local WordPress + MySQL environment in one command to run this repo |

## Skills this demonstrates

- **Content management** — pages, menus, widgets, structuring a small business site
- **Safe customization** — child themes instead of editing core/parent files directly
- **Plugin literacy** — installing/configuring plugins, and writing a minimal one when needed
- **Basic troubleshooting** — diagnosing the issues WP site owners most commonly report (see `docs/TROUBLESHOOTING.md`)
- **Environment setup** — comfortable spinning up WordPress locally via Docker for testing before touching a live site

## Running it locally

Requires Docker Desktop.

```bash
docker compose up -d
```

Then visit `http://localhost:8080` and complete the WordPress install screen. In **Appearance → Themes**, activate **Support Hub (Twenty Twenty-Four Child)**. In **Plugins**, activate **Simple FAQ Accordion**, then drop `[faq_accordion]` into any page to render the FAQ block.

phpMyAdmin is available at `http://localhost:8081` if you need to inspect the database.

## Notes

- `wp-config.php`, uploads, and core WordPress files are intentionally **not** committed — they're generated by the Docker image or a real WP install (see `.gitignore`). Committing only theme/plugin/docs code is standard practice for WP projects on GitHub.
- Sample content (pages/FAQ copy) lives in `docs/CONTENT-PLAN.md` rather than a database export, so it's readable directly on GitHub without needing to import anything.
